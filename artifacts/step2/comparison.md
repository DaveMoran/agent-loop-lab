When comparing both the OpenAI and the Anthropic response (as well as the requests), there are a few things that stick out to me immediately and things that make more sense as I dig in. First, the OpenAI response is much larger than the Anthropic one, almost triple the line size for a response. Part of this that is helpful is that it returns the entire definition of the tool that was called, meaning if search logs was called i can see in the log what all of the arguments it could have sent were. While this is a lot, it does also provide more context that could be useful while debugging. That being said, it also has a lot of fluff that would not be needed. For example, there is a "tool_usage" section that is separate from the "tools" section that is called. that section has a reference to things like "image_gen" that were not called in this run, so having it in the logs conflates the size that is returned.

On the other end, with Anthropic's response it is a lot more straightforward with its logs, allowing for a better "quick look" when going through what errors could have happened with its calls. That being said, it did use almost 5x the amount of tokens for the same prompt, so while the logs are smaller theres evidence that more "work" was done by the Agent.

Looking at the responses, we can see the difference between how each of the tools were called, and why we needed to set up different agent creations while still using the same tool definition. For example, Anthropic uses tool_use, and shows you the input and value it parsed for the item. OpenAI calls it a function_call, and actually shows all of the arguments it passed as a function call as opposed to Anthropic only sending the two specific arguments it needed. Anthropic sent it as a structured json object while OpenAI sent it as a string that can be parsed as a json object.

Both use a similar id setup with their tool calls. Anthropic uses content[x].id as "toolu_..." where toolu = Tool Use. OpenAI uses output[x].call_id = "call_...". Both of these objects use "name" to refer to the name of the tool used, so there's a similarity there, and are exported to custom fields (like tool_use_id) so that we can uniformly use the responses regardless of what model we use.
